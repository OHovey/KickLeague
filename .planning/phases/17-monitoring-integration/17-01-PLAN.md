<task type="auto">
  <name>Task 1: Install and configure Sentry for Next.js 16</name>
  <files>
    package.json
    sentry.client.config.ts
    sentry.server.config.ts
    sentry.edge.config.ts
    src/instrumentation.ts
    next.config.ts
    src/app/global-error.tsx
  </files>
  <action>
    1. Install @sentry/nextjs:
       `npm install @sentry/nextjs`

    2. Create `sentry.client.config.ts` at project root:
       - Import and call `Sentry.init()` with:
         - `dsn: process.env.NEXT_PUBLIC_SENTRY_DSN` (client needs NEXT_PUBLIC_ prefix)
         - `environment: process.env.NODE_ENV` (development vs production)
         - `tracesSampleRate: 0.1` (10% of transactions sampled -- low cost for a content site)
         - `replaysSessionSampleRate: 0` (no session replays -- not needed)
         - `replaysOnErrorSampleRate: 0` (no error replays -- not needed)
         - `debug: false`
       - Do NOT enable Replay integration (not needed for a content site)

    3. Create `sentry.server.config.ts` at project root:
       - Import and call `Sentry.init()` with:
         - `dsn: process.env.SENTRY_DSN`
         - `environment: process.env.NODE_ENV`
         - `tracesSampleRate: 0.1`
         - `debug: false`

    4. Create `sentry.edge.config.ts` at project root:
       - Same as server config but with edge-compatible settings:
         - `dsn: process.env.SENTRY_DSN`
         - `environment: process.env.NODE_ENV`
         - `tracesSampleRate: 0.1`
         - `debug: false`

    5. Create `src/instrumentation.ts`:
       - Export `async function register()` that conditionally imports:
         - `import './sentry.server.config'` when `process.env.NEXT_RUNTIME === 'nodejs'`
         - `import './sentry.edge.config'` when `process.env.NEXT_RUNTIME === 'edge'`
       - Export `const onRequestError = Sentry.captureRequestError` from @sentry/nextjs

    6. Update `next.config.ts`:
       - Import `withSentryConfig` from `@sentry/nextjs`
       - Wrap the final export: `export default withSentryConfig(withNextIntl(nextConfig), { ... })`
       - Sentry build options:
         - `org: process.env.SENTRY_ORG`
         - `project: process.env.SENTRY_PROJECT`
         - `silent: !process.env.CI` (quiet in dev, verbose in CI)
         - `widenClientFileUpload: true` (upload more client files for better source maps)
         - `hideSourceMaps: true` (don't expose source maps to users)
         - `disableLogger: true` (remove Sentry logger statements in production builds)
       - IMPORTANT: Preserve the existing security headers configuration and next-intl wrapping. The wrapping order should be: `withSentryConfig(withNextIntl(nextConfig), sentryOptions)`

    7. Create `src/app/global-error.tsx`:
       - This is a Next.js App Router convention file for catching unhandled errors
       - `'use client'` directive
       - Import `* as Sentry` from `@sentry/nextjs`
       - Use `useEffect` to call `Sentry.captureException(error)` on mount
       - Render a minimal error fallback UI: dark background, "Something went wrong" heading, "Try again" button that calls `reset()`
       - Style with inline styles (not Tailwind) since global-error replaces the entire HTML
  </action>
  <verify>

  </verify>
  <done>
    Sentry SDK installed and configured for client, server, and edge runtimes. Source map upload configured via withSentryConfig. Global error boundary catches unhandled errors and reports to Sentry. Build passes cleanly.
  </done>
