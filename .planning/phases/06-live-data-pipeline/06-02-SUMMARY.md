## Accomplishments
- Match completion chain: when pollActiveMatches detects a finished match, standings for the affected matchweek are recomputed from all fixtures and ISR pages are revalidated
- Daily resync refreshes all fixture data for 5 leagues, detects standings drift by comparing computed vs stored positions, and auto-corrects mismatches
- Vercel cron route at /api/cron/daily-resync triggers daily resync at 04:00 UTC with CRON_SECRET protection
- Error isolation: one failed match completion or league resync does not block others

## Decisions Made
- **Inlined standings algorithm:** Copied the TeamStats accumulation pattern from computeHistoricalStandings rather than extracting a shared utility. Rationale: seed code has chalk logging, bulk iteration, and seed-specific concerns. Coupling live pipeline to seed code would make both harder to change independently.
- **Drift detection scope:** Only checks the latest fully-completed matchweek (where all fixtures are finished). This catches the most impactful drift while keeping the operation lightweight.
- **Sequential league processing:** Daily resync processes one league at a time to avoid overwhelming API rate limits with parallel requests.
- **revalidatePath safety:** Wrapped in try/catch since it throws outside of a request context (e.g. unit tests).
