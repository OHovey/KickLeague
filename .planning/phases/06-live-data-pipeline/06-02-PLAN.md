<objective>
Build the match completion chain and daily resync pipeline. When match polling (Plan 06-01) detects a finished match, this plan's code recalculates standings and revalidates ISR pages. The daily resync catches any missed updates and auto-corrects data drift.

Purpose: Without the completion chain, polling detects updates but doesn't propagate them to standings or cached pages. Without daily resync, edge cases (missed polls, API downtime, postponements) cause stale data to persist indefinitely.

Output: `handleMatchCompletion` function wired into the poll handler, daily-resync logic with drift detection, and a Vercel cron-triggered route for the daily 04:00 UTC resync.
</objective>

  **1. Create `src/lib/pipeline/match-completion.ts`:**

  Export `handleMatchCompletion(fixtureDbId, leagueDbId, season, matchweek): Promise<CompletionResult>`:

  ```typescript
  interface CompletionResult {
    fixtureApiId: number;
    leagueSlug: string;
    matchweek: number;
    standingsUpdated: boolean;
    pagesRevalidated: string[];
  }
  ```

  Steps inside the function:
  a. **Recompute standings for the affected matchweek.** The core algorithm lives in `computeHistoricalStandings` in `src/lib/seed/compute-historical-standings.ts`. That function processes ALL matchweeks in bulk (designed for seeding), which is overkill for a single matchweek update.

  **Reuse strategy: inline the algorithm (copy the pattern, do NOT extract a shared utility).** Rationale: The seed function has chalk logging, bulk iteration over all matchweeks, and seed-specific concerns. Extracting a shared utility would couple the live pipeline to seed code, making both harder to change independently. Instead, copy the `TeamStats` interface and the accumulation logic (query finished fixtures up to matchweek N, accumulate stats per team, compute positions by sorting on points/GD/GF) directly into `match-completion.ts`. This is ~60 lines of straightforward logic.

  Specifically:
  - Define the same `TeamStats` interface locally in match-completion.ts.
  - Query ALL finished fixtures for this league+season up to (and including) the affected matchweek.
  - Accumulate stats per team using the same home/away split logic from `computeHistoricalStandings`.
  - Sort teams by points (desc), then goal difference (desc), then goals for (desc) to assign positions.
  - Upsert standings rows for the affected matchweek only (~20 rows).

  Use `buildConflictUpdateColumns` from `src/lib/seed/utils.ts` for the standings upsert, matching the pattern in `computeHistoricalStandings`.

  Set `updatedAt: new Date()` on all upserted standings rows -- this is what the browser polling endpoint checks.

  b. **Revalidate ISR pages.** Import `revalidatePath` from `next/cache`. Call it for:
  - `"/"` (home page shows league table)
  - `"/matches"` (match list page)

  Note: `revalidatePath` in Route Handlers is lazy (next visit triggers regeneration). This is fine -- browser poll will detect the `updatedAt` change and refetch via server actions.

  c. **Log the completion** with `console.log` using structured format: `{ event: "match_completed", fixtureId, league, matchweek, standingsUpdated: true }`.

  d. Return `CompletionResult`.

  **2. Wire `handleMatchCompletion` into `poll-active-matches.ts`:**

  In the `pollActiveMatches` function, after detecting a fixture status transition to "finished":
  - Import `handleMatchCompletion` from `./match-completion`.
  - Call `await handleMatchCompletion(fixtureDbId, leagueDbId, season, matchweek)` for each newly-completed match.
  - Include the completion results in the `PollResult` return value.

  If `handleMatchCompletion` throws, catch the error, log it, and continue processing other fixtures. Don't let one failed completion break the entire poll.

  **1. Create `src/lib/pipeline/daily-resync.ts`:**

  Export `dailyResync(): Promise<ResyncResult>`:

  ```typescript
  interface ResyncResult {
    leaguesResynced: number;
    fixturesUpdated: number;
    standingsCorrected: number;
    apiCallsUsed: number;
    errors: string[];
  }
  ```

  Steps:
  a. **Budget check:** Call `canMakePipelineCall()`. If budget exhausted, return early.
  b. **For each of the 5 leagues** (query leagues table, get all with their currentSeason):
     - Create `ApiFootballClient` with `useCache: false` (want fresh data).
     - Fetch all fixtures for the league-season via `/fixtures?league={apiId}&season={season}`.
     - Use `withRetry()` around the API call.
     - Log the API call via `logApiCall()`.
     - For each fixture in the response:
       - Map status using `mapStatus()`.
       - Upsert fixture (same pattern as seed-fixtures.ts).
       - Track if any status changed.
     - **Drift detection:** After upserting fixtures, recompute standings for the latest completed matchweek (query max matchweek where all fixtures for that matchweek are finished). Compare computed positions against stored positions. If any mismatch, log the discrepancy and overwrite with fresh computed data.
     - Call `revalidatePath("/")` and `revalidatePath("/matches")` if any data changed.
  c. **Skip player/squad data** during daily resync (per CONTEXT.md decision).
  d. Return `ResyncResult` with counts.

  Stagger league processing: process one at a time (not parallel) to be gentle on API rate limits.

  **2. Create `src/app/api/cron/daily-resync/route.ts`:**

  This uses Vercel's native cron (1/day fits Hobby plan). Protect with `CRON_SECRET`:

  ```typescript
  import type { NextRequest } from "next/server";
  import { dailyResync } from "@/lib/pipeline/daily-resync";

  export const maxDuration = 60;

  export async function GET(request: NextRequest) {
    const authHeader = request.headers.get("authorization");
    if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
      return new Response("Unauthorized", { status: 401 });
    }
    const result = await dailyResync();
    return Response.json(result);
  }
  ```

  **3. Update `vercel.json`** (created in Plan 06-01) to add the daily resync cron:

  ```json
  {
    "crons": [
      {
        "path": "/api/cron/daily-resync",
        "schedule": "0 4 * * *"
      }
    ]
  }
  ```

  Note: User needs to set `CRON_SECRET` in Vercel environment variables. This is auto-generated by Vercel when crons are configured, but can also be set manually.
