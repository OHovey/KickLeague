<task type="auto">
  <name>Task 1: Create sitemap migration verification script</name>
  <files>scripts/verify-sitemap-migration.ts</files>
  <action>
Create `scripts/verify-sitemap-migration.ts` — a Node.js script that:

1. **Reconstructs the old monolithic sitemap URLs** using the same logic as the deleted `sitemap.ts`:
   - Import `getAllTeamSlugs` and `getFinishedMatchIds` from `@/lib/seo/sitemap-queries`
   - Import `routing`, `locales` from `@/i18n/routing`
   - Port the `getLocalizedPath` helper from the old sitemap.ts
   - Build the complete set of old URLs:
     - Static: `/` and `/matches` (x5 locales each)
     - Teams: each slug (x5 locales)
     - Matches: each finished match ID (x5 locales)
   - Each URL = `{siteUrl}/{locale}{localizedPath}`

2. **Collects all new segmented sitemap URLs** by importing the `sitemapSegments` registry:
   - Import `sitemapSegments` from `@/lib/seo/sitemap-registry`
   - For each segment, call `fetchEntries()`
   - For each entry, generate all locale variant URLs using the same `getLocalizedPath` helper
   - Collect into a Set

3. **Compares old vs new:**
   - For each old URL, check if it exists in the new URL set
   - Report any missing URLs
   - Print summary: `{oldCount} old URLs, {newCount} new URLs, {missingCount} missing`

4. **Exit code:**
   - Exit 0 if no missing URLs
   - Exit 1 if any URLs are missing (with list of missing URLs)

The script should use `tsx` to run (already in devDependencies — check `package.json`). Add a note in the script header on how to run it:
```
// Usage: npx tsx scripts/verify-sitemap-migration.ts
```

If `tsx` is not available, use `ts-node` or `npx ts-node --esm`. Check package.json for which is available.

The script must handle the case where the database is not configured (e.g., in CI) — if `isDatabaseConfigured()` returns false, print a warning and exit 0 (can't verify without data).

Important: Use the siteUrl from env var `NEXT_PUBLIC_SITE_URL` or default to `https://kickleague.com`.
