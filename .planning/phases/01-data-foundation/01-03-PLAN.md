Build the data seeding pipeline that populates the database with current and previous season data for all 5 Big European leagues from API-Football.

Output: A CLI seed script with per-league and per-season support, plus a refresh mode for incremental updates during development.

    **src/lib/seed/utils.ts:**
    Implement the `buildConflictUpdateColumns` helper following the RESEARCH.md code example exactly:
    - Takes a Drizzle PgTable and array of column names to update on conflict
    - Returns a record mapping column names to `sql.raw('excluded.{colName}')` for use in `onConflictDoUpdate.set`

    - `delay(ms: number): Promise<void>` -- simple sleep helper for rate limit display

    **src/lib/seed/seed-leagues.ts:**
    Export `async function seedLeagues(db, client, seasons)`:
    - Fetch league data from `/leagues?id={leagueId}` for each of the 5 leagues
    - Upsert into `leagues` table using apiId as conflict target
    - For each league+season, upsert into `league_config` with:
      - teamCount from API response
      - tiebreakerOrder: hardcode the correct order per league from spec (e.g., "goal_difference,goals_for,head_to_head" for Premier League, "head_to_head,goal_difference,goals_for" for La Liga/Serie A)
      - matchweeksTotal: derive from teamCount (teamCount=20 -> 38, teamCount=18 -> 34)
      - Coverage flags (hasXg, hasDetailedStats, hasPlayerStats) from API-Football league coverage response
    - For each league+season, upsert `league_zones` rows with the zone data from the spec:
      - Premier League: CL 1-4 (#22c55e), EL 5 (#3b82f6), ECL 6 (#93c5fd), REL 18-20 (#ef4444)
      - La Liga: CL 1-4 (#22c55e), EL 5 (#3b82f6), ECL 6 (#93c5fd), REL 18-20 (#ef4444)
      - Bundesliga: CL 1-4 (#22c55e), EL 5 (#3b82f6), ECL 6 (#93c5fd), REL_PO 16 (#f59e0b), REL 17-18 (#ef4444)
      - Serie A: CL 1-4 (#22c55e), EL 5 (#3b82f6), ECL 6 (#93c5fd), REL 18-20 (#ef4444)
      - Ligue 1: CL 1-3 (#22c55e), CL_Q 4 (#86efac), EL 5 (#3b82f6), REL_PO 16 (#f59e0b), REL 17-18 (#ef4444)
    - Log progress with chalk: league name + season being seeded

    **src/lib/seed/seed-teams.ts:**
    Export `async function seedTeams(db, client, leagueDbId, leagueApiId, season)`:
    - Fetch from `/teams?league={apiId}&season={year}`
    - Map API response to teams table shape: apiId, leagueId (db ID), slug (generate from team name -- lowercase, hyphens), name, shortName (team.code or first 3 chars), abbreviation (team.code), logoUrl, stadiumName (venue.name), founded, country
    - Upsert into teams using apiId as conflict target, updating name, shortName, logoUrl, stadiumName
    - Return a map of `apiId -> dbId` for use by downstream seeders
    - Log: "[5/5] Seeded 20 teams for Premier League 2025"

    **src/lib/seed/seed-players.ts:**
    Export `async function seedPlayers(db, client, teamApiIdToDbId, leagueApiId, season)`:
    - For each team, fetch from `/players/squads?team={teamApiId}`
    - Map response to players table: apiId, teamId (db ID from map), name, firstName, lastName (split from name if needed), position, number, nationality (if available), photoUrl, age
    - Upsert using apiId as conflict target
    - Log progress per team: "[12/20] Seeding players for Arsenal..."

    **src/lib/seed/seed-fixtures.ts:**
    Export `async function seedFixtures(db, client, leagueDbId, leagueApiId, season, teamApiIdToDbId)`:
    This is the most complex seeder. Two-phase approach:

    Phase A -- Basic fixture data:
    - Fetch from `/fixtures?league={apiId}&season={year}` (1 API call, returns all fixtures)
    - Upsert basic fixture data into `fixtures` table: apiId, leagueId, season, matchweek (fixture.league.round -- extract number), homeTeamId, awayTeamId (lookup from teamApiIdToDbId), kickoff, status, homeScore, awayScore, referee, venue
    - Build a map of `fixtureApiId -> fixtureDbId`

    Phase B -- Detailed fixture data (events + stats):
    - Filter to finished fixtures only (no point fetching details for scheduled matches)
    - Chunk fixture API IDs into batches of 20
    - For each batch, fetch from `/fixtures?ids={comma-separated-ids}` (returns events, statistics, etc.)
    - For each fixture in the response:
      - Upsert `fixture_events`: map each event to fixtureId (db), type (map API type to our enum), minute, extraMinute, teamId (lookup), playerId (lookup from players table by API ID, nullable if not found), assistPlayerId, detail
      - Upsert `fixture_stats`: for each team's statistics array, map to our columns (possession, shots, shotsOnTarget, corners, fouls, offsides, yellowCards, redCards, xg). Handle null values and API-Football's string-number format (e.g., "67%" for possession -> 67.0).
    - Log progress: "[3/19] Fetching detailed fixtures batch..." and total events/stats inserted

    **Important:** API-Football returns statistics as an array of `{ type: string, value: string|number|null }` objects. These need to be mapped to our typed columns. Common mappings:
    - "Ball Possession" -> possession (strip %, parse as real)
    - "Total Shots" -> shots
    - "Shots on Goal" -> shotsOnTarget
    - "Corner Kicks" -> corners
    - "Fouls" -> fouls
    - "Offsides" -> offsides
    - "Yellow Cards" -> yellowCards
    - "Red Cards" -> redCards
    - "expected_goals" -> xg

    **src/lib/seed/seed-standings.ts:**
    Export `async function seedStandings(db, client, leagueDbId, leagueApiId, season, teamApiIdToDbId)`:
    - Fetch from `/standings?league={apiId}&season={year}` (returns current standings with full data)
    - The API returns a single standings snapshot (the latest). Store this as the current matchweek's standings.
    - Determine current matchweek from the standings data or from the last played fixture
    - Upsert into standings: leagueId, season, matchweek, teamId, position (rank), played, won, drawn, lost, goalsFor, goalsAgainst, goalDifference, points, form (string from API), homeWon/Drawn/Lost/GoalsFor/GoalsAgainst, awayWon/Drawn/Lost/GoalsFor/GoalsAgainst, pointsDeduction (goalsDiff vs calculated -- detect deductions), updatedAt
    - Use (leagueId, season, matchweek, teamId) as unique conflict target
    - Log: "Seeded standings for Premier League 2025 (matchweek 23, 20 teams)"

    **src/lib/seed/index.ts:**
    Create the CLI entrypoint using commander, following the RESEARCH.md pattern:

    ```
    program
      .name('seed')
      .description('Seed FootballPulse database from API-Football')
      .option('--league <slug>', 'Seed specific league: premier-league, la-liga, bundesliga, serie-a, ligue-1')
      .option('--all', 'Seed all 5 leagues')
      .option('--refresh', 'Only fetch data newer than last seed')
      .option('--season <year>', 'Specific season year', '2025')
      .option('--no-cache', 'Bypass file cache (consumes API quota)')
    ```

    The action handler must:
    1. Load dotenv config
    2. Validate that DATABASE_URL and API_FOOTBALL_KEY are set
    3. Create ApiFootballClient instance with cache options
    4. Import db from connection module
    5. Determine which leagues to seed (--all = all 5, --league = one)
    6. Determine seasons to seed (default: [2025, 2024] for current + previous. If --season provided, just that one)

    Orchestration order per league per season:
    1. `seedLeagues()` -- leagues, config, zones (only needs to run once for all seasons)
    2. `seedTeams()` -- returns teamApiIdToDbId map
    3. `seedPlayers()` -- uses team map
    4. `seedFixtures()` -- uses team map, writes fixtures + events + stats
    5. `seedStandings()` -- uses team map

    After each league-season completes, log a summary:
    - League name + season
    - Teams, fixtures, events, players, standings rows inserted/updated
    - API quota remaining (from DailyQuotaTracker)
    - Cache hit rate if available

    At the end, log total summary across all leagues.

    Handle errors gracefully:
    - If a specific league-season fails, log the error and continue with the next one (don't abort everything)
    - If daily quota is exhausted, log a clear message: "Daily API quota exhausted. Re-run tomorrow -- cached data will be reused automatically."
    - Wrap the entire action in try/catch, log any uncaught errors with full stack trace

    **For --refresh mode:**
    - Only fetch fixtures with status != 'finished' (scheduled, postponed) and re-fetch their details
    - Re-fetch standings (always current)
    - Skip teams and players (they don't change during a season)
    - This is a lightweight mode for keeping dev data fresh without a full reseed

    **package.json:**
    Add script: `"seed": "tsx src/lib/seed/index.ts"`

    This allows: `npm run seed -- --all` or `npm run seed -- --league premier-league --season 2024`
