       - Export `getZoneColor(zones, position)` - returns hex color string or null

    2. Create src/lib/standings/queries.ts:
       - Import db from connection, schema tables
       - Import calculateStandings from './calculate' (from Plan 01)
       - Export `getLeagueBySlug(slug)` - fetches league row by slug
       - Export `getLeagueConfig(leagueId, season)` - fetches league_config row
       - Export `getLeagueZones(leagueId, season)` - fetches all zone rows for league+season
       - Export `getStandingsWithZones(leagueSlug, season?)`:
         1. Fetch league by slug
         2. Fetch league config for current season
         3. Fetch raw standings for latest matchweek
         4. Fetch zones
         5. Apply tiebreakers via calculateStandings if needed (pass fixtures for H2H)
         6. Return { standings, zones, config, league }

    **Tiebreaker integration strategy:**
    The seed script (Phase 1) already stores standings with `position` field correctly sorted.
    The calculateStandings function from Plan 01 is designed for re-sorting when needed (e.g., mid-matchweek updates).
    For query-time: Call calculateStandings when fetching standings to ensure any late updates are correctly sorted.
    Pass fixtures data to enable H2H calculation for La Liga/Serie A.

    getStandingsWithZones implementation:
    1. Fetch raw standings rows for league+season+matchweek
    2. Fetch fixtures for season (needed for H2H tiebreaker)
    3. Fetch league config (contains tiebreakerOrder string)
    4. Call calculateStandings(rows, config, fixtures) to apply tiebreakers
    5. Return sorted standings with positions updated
  </action>
