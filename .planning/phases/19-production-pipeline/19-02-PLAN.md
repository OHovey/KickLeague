  <files></files>
  <action>
Run verification checks against the production database to confirm data is current:

1. **Run the verify-db script against production:**
   ```bash
   DATABASE_URL=$PRODUCTION_DATABASE_URL npx tsx scripts/verify-db.ts
   ```
   Use the production DATABASE_URL from `.env.local` (the Neon production connection string). If the env var is named differently, check `.env.local` for the production database URL.

   This script checks: leagues (5), teams (90-120), fixtures (2000-4000), standings (>500), and per-league breakdowns.

2. **Check api_call_log for recent pipeline activity:**
   Run a quick SQL query via the verify-db pattern (or use `npx tsx` with an inline script) to check if there are recent entries in `api_call_log` from the last hour:
   ```sql
   SELECT COUNT(*) as recent_calls,
          MAX(called_at) as last_call,
          MIN(called_at) as first_call
   FROM api_call_log
   WHERE called_at > NOW() - INTERVAL '1 hour';
   ```

   If there are 0 recent calls, the QStash schedule may not be firing correctly or there may be no active match windows right now (which is fine -- the pipeline correctly skips polling when no matches are active).

3. **Check fixture freshness -- look at the most recently updated fixtures:**
   ```sql
   SELECT f.api_id, l.slug, f.status, f.kickoff, f.home_score, f.away_score
   FROM fixtures f
   JOIN leagues l ON l.id = f.league_id
   WHERE f.kickoff > NOW() - INTERVAL '7 days'
   ORDER BY f.kickoff DESC
   LIMIT 20;
   ```

   This shows the most recent fixtures. Verify:
   - Completed matches have scores filled in (not null)
   - Fixtures have correct statuses (finished for past, scheduled for future)
   - Data matches what API-Football would show

4. **Check standings recency:**
   ```sql
   SELECT l.slug, s.season, MAX(s.matchweek) as latest_mw, MAX(s.updated_at) as last_updated
   FROM standings s
   JOIN leagues l ON l.id = s.league_id
   GROUP BY l.slug, s.season
   ORDER BY l.slug;
   ```

   The `updated_at` for each league should be recent if matches have been completed since deployment.

Log all results in the summary. The key question is: "Is the pipeline keeping data fresh?" If no matches have occurred since deployment, the seeded data from 18-02 is still current and that's fine -- the pipeline will update when matches next occur.
