  <name>Task 1: Create in-memory rate limiter module</name>
  <files>src/lib/rate-limit.ts</files>
  <action>
Create `src/lib/rate-limit.ts` implementing a simple in-memory token bucket rate limiter. No external dependencies (no Redis, no npm packages for this).

**Data structures:**
- `ipBuckets: Map<string, { tokens: number; lastRefill: number }>` — per-IP token buckets
- `globalBucket: { tokens: number; lastRefill: number }` — single global bucket shared across all IPs

**Configuration type:**
```typescript
interface RateLimitConfig {
  /** Max tokens per IP per refill window */
  maxTokensPerIp: number;
  /** Refill window in milliseconds (60_000 = 1 minute) */
  windowMs: number;
  /** Global ceiling — max requests across ALL IPs per window */
  globalMax: number;
  /** Identifier for logging (e.g. 'updates/check', 'clicks') */
  endpoint: string;
}
```

**Exported function:**
```typescript
export interface RateLimitResult {
  allowed: boolean;
  retryAfterSeconds: number;
}

export function rateLimit(ip: string, config: RateLimitConfig): RateLimitResult
```

**Algorithm (token bucket with lazy refill):**
1. Get or create the IP bucket and the global bucket
2. For each bucket: calculate elapsed time since `lastRefill`. If >= `windowMs`, reset tokens to max and update `lastRefill`.
3. If EITHER bucket has 0 tokens, return `{ allowed: false, retryAfterSeconds }` where retryAfterSeconds is `Math.ceil((windowMs - elapsed) / 1000)`.
4. If both have tokens, decrement both and return `{ allowed: true, retryAfterSeconds: 0 }`.

**Logging on deny:**
When `allowed === false`, log to console: `[rate-limit] 429 | endpoint=${config.endpoint} | ip=${ip} | time=${new Date().toISOString()}`

**Cleanup:** Add a periodic cleanup (every 5 minutes via `setInterval` at module scope) that removes IP entries older than 2x the window to prevent memory leaks. Use a module-level `let lastCleanup = Date.now()` check inside `rateLimit()` instead of `setInterval` (safer for serverless — no dangling timers). If `Date.now() - lastCleanup > 5 * 60 * 1000`, iterate the map and delete stale entries, then update `lastCleanup`.

**Pre-configured instances — export two config objects:**
```typescript
export const RATE_LIMIT_UPDATES: RateLimitConfig = {
  maxTokensPerIp: 30,
  windowMs: 60_000,
  globalMax: 300,  // 10x per-IP — handles ~10 concurrent unique IPs maxing out
  endpoint: 'updates/check',
};

export const RATE_LIMIT_CLICKS: RateLimitConfig = {
  maxTokensPerIp: 10,
  windowMs: 60_000,
  globalMax: 100,
  endpoint: 'clicks',
};
```

Do NOT expose X-RateLimit-Remaining or similar headers — per user decision, don't reveal limits to attackers.
