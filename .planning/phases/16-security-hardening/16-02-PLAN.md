**Add `headers` to the config object. The headers function returns an array of header rules:**

```typescript
const nextConfig: NextConfig = {
  async headers() {
    return [
      {
        source: '/(.*)',
        headers: securityHeaders,
      },
    ];
  },
};
```

**Define `securityHeaders` array above the config:**

**1. Content-Security-Policy** — Start in **report-only mode** (`Content-Security-Policy-Report-Only`) to avoid breaking anything on first deploy. Once verified in production logs, it can be switched to enforcing `Content-Security-Policy`.

CSP directives (all on one line, semicolon-separated):
- `default-src 'self'` — fallback for anything not explicitly listed
- `script-src 'self' 'unsafe-inline' 'unsafe-eval' https://pagead2.googlesyndication.com https://adservice.google.com https://www.googletagservices.com https://www.googletagmanager.com https://partner.googleadservices.com` — own scripts + AdSense + Google Tag Manager (future analytics). `'unsafe-inline'` needed for Next.js inline scripts and AdSense push. `'unsafe-eval'` needed for AdSense.
- `style-src 'self' 'unsafe-inline' https://fonts.googleapis.com` — own styles + Google Fonts (loaded by next/font) + inline styles from Tailwind/motion
- `img-src 'self' data: https://media.api-sports.io https://pagead2.googlesyndication.com https://*.googleusercontent.com blob:` — own images, team logos from API-Football, ad images, data URIs for inline SVGs
- `font-src 'self' https://fonts.gstatic.com` — Google Fonts files
- `connect-src 'self' https://pagead2.googlesyndication.com https://*.google-analytics.com https://*.analytics.google.com https://*.googletagmanager.com` — fetch/XHR destinations for ads and analytics
- `frame-src https://googleads.g.doubleclick.net https://tpc.googlesyndication.com https://www.google.com` — AdSense iframes
- `object-src 'none'` — block Flash/Java plugins
- `base-uri 'self'` — prevent base tag hijacking
- `form-action 'self'` — forms can only submit to own origin
- `frame-ancestors 'none'` — equivalent to X-Frame-Options DENY in CSP
- `report-uri /api/csp-report` — violations reported to logging endpoint
- `report-to csp-endpoint` — newer reporting API

Build the CSP string as a single template literal for readability, then `.replace(/\s{2,}/g, ' ').trim()` to collapse whitespace.

**2. X-Frame-Options:** `DENY` (per user decision — block all framing)

**3. X-Content-Type-Options:** `nosniff` (prevent MIME type sniffing)

**4. Referrer-Policy:** `strict-origin-when-cross-origin` (per user decision — full URL to same-origin, origin only to cross-origin)

**5. Permissions-Policy:** Deny all unnecessary browser features:
`camera=(), microphone=(), geolocation=(), interest-cohort=(), payment=(), usb=(), magnetometer=(), gyroscope=(), accelerometer=()`
Note: geolocation=() is denied — the site uses IP-based geo-detection via Vercel headers, not the browser Geolocation API.

**6. Report-To header:** JSON blob configuring the reporting endpoint:
```
{"group":"csp-endpoint","max_age":10886400,"endpoints":[{"url":"/api/csp-report"}]}
```

Create `src/app/api/csp-report/route.ts` to receive and log CSP violation reports.

**Route handler:**

```typescript
import { NextResponse } from 'next/server';

export const dynamic = 'force-dynamic';

/**
 * POST /api/csp-report
 *
 * Receives Content Security Policy violation reports from browsers.
 * Logs them server-side for monitoring — no database storage needed
 * at this scale. In production, these logs go to Vercel's log drain
 * (or Sentry once monitoring is set up in Phase 17).
 */
export async function POST(request: Request) {
  try {
    const body = await request.json();

    // Browsers send reports in two formats:
    // 1. Legacy: { "csp-report": { ... } }
    // 2. Reporting API: { "type": "csp-violation", "body": { ... } }
    const report = body['csp-report'] ?? body.body ?? body;

    console.warn('[csp-report]', JSON.stringify({
      blockedUri: report['blocked-uri'] ?? report.blockedURL ?? 'unknown',
      violatedDirective: report['violated-directive'] ?? report.effectiveDirective ?? 'unknown',
      documentUri: report['document-uri'] ?? report.documentURL ?? 'unknown',
      timestamp: new Date().toISOString(),
    }));

    // Always return 204 No Content — browsers don't care about the response body
    return new NextResponse(null, { status: 204 });
  } catch {
    // Malformed report — still return 204 to prevent browser retries
    return new NextResponse(null, { status: 204 });
  }
}
```

**Key design decisions:**
- Always return 204 regardless of parse success — browsers will retry on non-2xx which wastes bandwidth
- Extract only the fields useful for debugging (blocked URI, violated directive, document URI)
- Use `console.warn` (not `console.log`) so CSP violations stand out in production logs
- No rate limiting on this endpoint — it receives browser-initiated reports only and returning 204 is cheap
- No database storage — at this scale, structured logging to stdout is sufficient (Phase 17 will add Sentry which can capture these)
